Data Integration

CALS Data

Synchronizing institutional people, employment, and organizational data for downstream CALS systems.

Ruby on Rails · MySQL · REST APIs · Docker · Background Jobs

The system

CALS Data is a long-running Rails application that synchronizes institutional data into CALS-managed systems. It has continued evolving as university data sources, APIs, organizational structures, and business requirements have changed.

My contribution

  • Develop and maintain Rails services responsible for institutional data synchronization.
  • Integrate with campus APIs that provide people, employment, and organizational data.
  • Design synchronization and reconciliation processes that identify missing, changed, inactive, or inconsistent records.
  • Maintain the relational data model and supporting MySQL queries.
  • Support scheduled processing, auditing, notifications, deployment, and long-term production operation.

Why it matters

This project represents one of the most important lessons from long-term application ownership: enterprise software needs to adapt as the systems around it change. CALS Data has continued serving that role through multiple generations of institutional data sources.

Rails API

Workday Role Access

A backend API supporting CALS workflows for requesting and managing Workday security-role access.

Rails · MySQL · Vue.js · OIDC · OAuth 2.0 · PKCE · Pundit

The system

Workday Role Access supports the workflow used to request and manage access to Workday security roles. The application follows CALS IT's newer frontend/backend architecture, pairing a Vue.js client with a Rails API.

My contribution

  • Design and develop the Rails REST API used by the Vue.js frontend.
  • Participate in requirements gathering and relational database design.
  • Implement authentication using OpenID Connect, Authorization Code flow, and PKCE.
  • Validate JWTs and apply policy-based authorization to application resources.
  • Design predictable API responses and error handling for frontend consumers.

What it demonstrates

This project represents the evolution of my role from traditional full-stack Rails development toward backend APIs that serve independently developed frontend applications.

Web & Mobile

ARS Portal

One Rails application delivered through the web, iOS, and Android using Hotwire Native.

Rails · Hotwire · Stimulus · Hotwire Native · iOS · Android

The system

ARS Portal provides digital services for Agricultural Research Stations. Rather than building three independent applications, the project uses Rails as the primary application while native iOS and Android clients provide access to the same workflows.

My contribution

  • Develop the Rails application and server-driven business workflows.
  • Build and configure native iOS and Android shells using Hotwire Native.
  • Keep business rules centralized in Rails instead of duplicating application logic across platforms.
  • Handle mobile-specific configuration and application behavior where native functionality is required.
  • Support deployment and ongoing development across all three application targets.

What it demonstrates

ARS Portal expanded my Rails experience into cross-platform application development while retaining the maintainability and server-driven architecture that make Rails effective for business applications.

Rails · Ruby · MySQL · APIs · Background Jobs · Email

The system

CALS Notifications is a long-running Rails application that automates scheduled operational tasks, system audits, data synchronization, and notifications across several CALS IT processes.
