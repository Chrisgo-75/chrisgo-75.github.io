About

More than a decade building and supporting production applications.

I'm Chris Arndt, a backend and application developer with professional experience building and supporting software at the University of Wisconsin–Madison's College of Agricultural and Life Sciences since 2011.

I began my application-development career building custom PHP applications and transitioned to Ruby on Rails early in my career. Over the years, my responsibilities expanded beyond application code into database design, authentication, integrations, deployment, Linux server administration, and long-term production support.

Today, my work is increasingly focused on Rails APIs, enterprise integrations, MySQL and Oracle databases, institutional APIs, authentication and authorization, and backend services supporting modern frontend applications. More recently, I've also expanded into Rails-powered iOS and Android development using Hotwire Native.

How I Work

How I approach software development

Good software starts with understanding the problem and continues long after the first production deployment.

Understand the business problem

I enjoy understanding why an application is needed before deciding how it should be built. Requirements gathering, workflow analysis, data modeling, and architecture are often just as important as writing the code itself.

Build for maintainability

I've maintained many of the systems I've developed long after their initial launch. That experience has made clear architecture, understandable code, reliable deployments, and operational visibility important parts of how I design applications.

Own more than the code

My experience extends across the application lifecycle: databases, authentication, APIs, containers, Linux servers, CI/CD, certificates, upgrades, troubleshooting, monitoring, and production support.

Collaborate across specialties

Modern applications are increasingly team efforts. I work closely with frontend developers, stakeholders, data teams, infrastructure staff, and other developers to turn business requirements into reliable production systems.

Career Evolution

From full-stack development to APIs and integrations

For much of my career, I developed complete Ruby on Rails applications. That included database design, Rails models and controllers, server-rendered interfaces, authentication, background processing, deployment, and production support.

Beginning in 2025, CALS underwent a major IT reorganization that brought previously distributed departmental IT groups into a centralized CALS IT organization. Application development became more collaborative and increasingly specialized between frontend and backend responsibilities.

As that model evolved, my work shifted toward backend architecture: designing Rails APIs, building relational databases, integrating institutional systems, working with Oracle and MySQL data, implementing authentication and authorization, and providing backend services consumed by Vue.js applications.

That change has allowed me to build on my full-stack background while developing deeper experience in APIs, integrations, data systems, security, and application architecture.

PHP → Full-Stack Rails → Rails APIs → Enterprise Integrations → Hotwire Native

Application Ownership

Building software that lasts

Some of the applications I work with have been in production for many years. Systems such as CALS Data and CALS Notifications have continued evolving as university systems, APIs, infrastructure, and business requirements have changed.

Long-term ownership has taught me that software development doesn't end when an application is deployed. Production systems require upgrades, security maintenance, database changes, integration updates, documentation, monitoring, troubleshooting, and ongoing support.

I value building systems that can continue changing without requiring them to be rewritten every time the environment around them changes.

Continuing to Learn

Learning new approaches when they solve real problems

I still enjoy exploring new technologies, especially when they provide a practical improvement over an existing approach.

In 2026, that meant expanding beyond traditional Rails web development into Hotwire Native and developing a Rails-powered application delivered through web, iOS, and Android clients.

The architecture keeps business logic and most application behavior in Rails while lightweight native applications provide access to platform-specific capabilities.
